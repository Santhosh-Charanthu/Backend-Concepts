SQL

SQL databases are relational databases that store data in tables with predefined schemas and support relationships through keys and constraints.

NoSQL

NoSQL databases are non-relational databases that provide flexible schemas and are designed to handle large-scale, distributed data efficiently.

Interview question

What is the difference between SQL and NoSQL

I wouldn’t say SQL is relational and NoSQL is non-relational, because that doesn’t really help me decide which one to use. I’d distinguish them based on how they handle data, relationships, consistency, and scaling.

SQL databases are my default when the data has strong relationships and I need reliable transactions and consistency. For example, in an e-commerce system, an order is related to a user, products, payments, and inventory. I can model those relationships explicitly and use transactions to make sure operations like placing an order either fully succeed or fail.

NoSQL databases become attractive when I have a huge amount of data, very high traffic, or data whose structure changes frequently, and I can design my data model around the queries rather than around relationships. For example, for a social-media feed, I might store a user's feed in a way that's optimized for quickly fetching it, rather than performing multiple joins every time.

The biggest practical difference for me is that SQL generally gives me powerful relational querying and strong transactional guarantees, while NoSQL often gives me more flexibility in data modeling and makes certain horizontal-scaling and high-throughput workloads easier.

What is an Index?

An index is a special data structure that allows the database to locate records quickly without scanning the entire table.

Why Not Index Every Column?

Indexes improve read performance but increase storage usage and write overhead because the database must update the index whenever data is inserted, updated, or deleted.
