Backend Interview Q&A

What is an API?

An API, or Application Programming Interface, is a contract that enables communication between different software systems. A client sends a request to an API endpoint, the server processes the request, interacts with the database or business logic if required, and returns a response. APIs help separate the frontend from the backend while providing a secure and structured way to exchange data.

What happens internally when a client calls an API?

When a client calls an API, it sends an HTTP request to a specific endpoint. The backend receives the request, executes the required business logic, interacts with the database if necessary, and generates a response. The response is then sent back to the client, typically in JSON format.

What does "API is a contract" mean?

API is called a contract because it defines a predefined agreement between the client and server regarding endpoints, request formats, and response structures. Both sides must follow this contract for communication to work correctly.

What is REST?

REST is an architectural style for designing APIs where resources are exposed through URLs and accessed using standard HTTP methods such as GET, POST, PUT, and DELETE. REST APIs are stateless and widely used because they are simple and scalable.

What is GraphQL?

GraphQL is a query language for APIs that allows clients to request exactly the data they need. Unlike REST, where the server determines the response structure, GraphQL gives the client control over the returned data, reducing over-fetching and under-fetching.

What are HTTP Methods?

HTTP methods define the action a client wants to perform on a resource. GET retrieves data, POST creates resources, PUT replaces resources, PATCH updates specific fields, and DELETE removes resources. They help APIs clearly communicate the intent of a request and follow RESTful conventions.

Why shouldn't GET modify data?

GET should not modify data because it is intended to be a read-only operation. Browsers, caches, search engine crawlers, and other systems assume GET requests are safe and can be executed multiple times without changing server state.
