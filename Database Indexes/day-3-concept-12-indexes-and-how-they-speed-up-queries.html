Day 3 — Concept 12: Indexes and How They Speed Up Queries

What is an Index?

An index is a special data structure that improves query performance by allowing the database to locate records quickly without scanning the entire table.

Most databases implement indexes using:

B-Tree

data structures.

Why Do We Need Indexes?

Imagine a table containing:

10 Million Records

Query:

SELECT *
FROM students
WHERE email='santhosh@gmail.com';

Without an index, the database may need to inspect every row until it finds the matching record.

This becomes slow as the table grows.

What is a Full Table Scan?

A Full Table Scan occurs when the database examines every row in a table to find matching records.

Example:

Row 1
Row 2
Row 3
...
Row N

Database checks rows one by one.

Real-Life Analogy

Imagine finding a topic in a 500-page textbook.

Without Index

Page 1
Page 2
Page 3
...
Page 500

Search manually.

With Index

ACID Properties → Page 220

Jump directly.

How Index Works

Suppose table:

id name
1 Rahul
2 Priya
3 Santhosh
4 Ajay

Index:

Ajay      → Row 4
Priya     → Row 2
Rahul     → Row 1
Santhosh  → Row 3

The database searches the index first and then jumps directly to the required row.

⏱️Time Complexity

Without Index

O(n)

Full Table Scan.

With B-Tree Index

O(log n)

Efficient search.

Creating an Index

Example:

CREATE INDEX idx_email
ON students(email);

Now queries searching by email become much faster.

Why Not Index Every Column?

Many beginners think:

More Indexes = Better Performance

❌ Wrong

Indexes have costs.

Cost 1: Extra Storage

Database stores:

Table Data
+
Index Data

More disk space is required.

Cost 2: Slower Inserts

When inserting a record:

INSERT INTO students(...)

Database must:

Insert Row
+
Update Index

Extra work.

Cost 3: Slower Updates

Updating an indexed column requires updating the index structure.

Cost 4: Slower Deletes

Deleting a row requires removing corresponding index entries.

Read vs Write Trade-Off

Reads

Faster

Writes

Slower

because indexes must be maintained.

Primary Key Index

Example:

CREATE TABLE students(
   id INT PRIMARY KEY
);

Most databases automatically create an index on the primary key.

Unique Index

Example:

CREATE UNIQUE INDEX idx_email
ON users(email);

Benefits:

Fast Search
No Duplicate Values

Composite Index

Index on multiple columns.

Example:

CREATE INDEX idx_dept_batch
ON students(department,batch);

Useful for:

SELECT *
FROM students
WHERE department='CSE'
AND batch=2027;

Top 10 Interview Questions with Answers

Q1. What is an Index?

Answer

An index is a special data structure that improves query performance by allowing the database to locate records quickly without scanning the entire table. Most databases use B-Tree structures to implement indexes.

Q2. What problem does an Index solve?

Answer

An index reduces the need for full table scans by enabling efficient lookups, significantly improving query performance on large datasets.

Q3. What is a Full Table Scan?

Answer

A full table scan occurs when the database examines every row in a table to find matching records because no suitable index is available.

Q4. How does an Index improve query performance?

Answer

Instead of scanning all rows, the database searches the index structure first and directly locates the matching records, reducing search time.

Q5. What data structure is commonly used for database indexes?

Answer

Most relational databases use B-Tree data structures to implement indexes because they provide efficient search, insertion, and deletion operations.

Q6. Why shouldn't we create indexes on every column?

Answer

Indexes consume additional storage and increase write overhead because the database must maintain the index whenever data is inserted, updated, or deleted.

Q7. How do indexes affect read and write performance?

Answer

Indexes improve read performance by enabling faster lookups, but they reduce write performance because index structures must be updated whenever data changes.

Q8. What is a Primary Key Index?

Answer

A Primary Key Index is an index automatically created by most databases on a primary key column, enabling fast lookups and ensuring uniqueness.

Q9. What is a Unique Index?

Answer

A Unique Index ensures that all values in the indexed column are unique while also improving query performance.

Example:

Email Address
Username

Q10. What is a Composite Index?

Answer

A Composite Index is an index created on multiple columns and is useful when queries frequently filter using those columns together.

Example:

(department, batch)

60-Second Interview Summary

An index is a special data structure that improves query performance by allowing the database to locate records efficiently without performing a full table scan. Most databases use B-Tree indexes, reducing search complexity from O(n) to approximately O(log n). Indexes are commonly created on frequently searched, filtered, joined, or sorted columns. While indexes significantly improve read performance, they introduce additional storage requirements and write overhead because index structures must be maintained whenever data changes. Common types include Primary Key Indexes, Unique Indexes, and Composite Indexes. 🚀
