Day 2 — Concept 7: Session-Based Authentication Notes

What is Session-Based Authentication?

Session-based authentication is a stateful authentication mechanism where the server stores user session information and uses a unique Session ID to identify the user in future requests.

      ↓
Server Finds Session
      ↓
User Authenticated

What is a Session?

A session is server-side storage that maintains information about an authenticated user between requests.

Example:

Session ID = ABC123

User ID = 101
Role = Student
Logged In = True

What is a Session ID?

A Session ID is a unique identifier generated by the server when a user successfully logs in.

Example:

ABC123

The Session ID acts as a key to locate the user's session data.

What is Stored in the Cookie?

The browser stores:

sessionId=ABC123

Only the Session ID is stored in the cookie.

The actual user information remains on the server.

✅Advantages

Secure

Only Session ID is sent to the client.

Easy Logout

Deleting session immediately logs out the user.

Immediate Session Revocation

Server can invalidate sessions instantly.

❌Disadvantages

Server Memory Usage

Every logged-in user requires session storage.

Scaling Complexity

Multiple servers require:

  • Sticky Sessions
  • Shared Session Store

Stateful Architecture

Server must maintain session data.

30-Second Revision

Session-based authentication is a stateful authentication mechanism where the server stores user session information and associates it with a unique Session ID. The Session ID is stored in a browser cookie and sent with future requests. The server uses the Session ID to locate the corresponding session and authenticate the user.

Top 10 Interview Questions with Answers

Q1. What is Session-Based Authentication?

Answer

Session-based authentication is a stateful authentication mechanism where the server stores user session information and identifies users using a unique Session ID.

Q2. What is a Session?

Answer

A session is server-side storage that maintains information about an authenticated user between requests.

Q3. What is a Session ID?

Answer

A Session ID is a unique identifier generated by the server when a user logs in. It is used to locate the corresponding session data.

Q4. What is stored in the browser during session authentication?

Answer

The browser stores only the Session ID inside a cookie. User information remains on the server.

Q5. What is stored on the server?

Answer

The server stores session data such as User ID, role, permissions, and login state associated with a Session ID.

Q6. Why is Session Authentication Stateful?

Answer

Session authentication is stateful because the server stores user-specific session information between requests and uses it for future authentication.

Q7. What happens when a user logs out?

Answer

The server deletes the user's session data, making the Session ID invalid and immediately logging the user out.

Q8. What problem occurs in a load-balanced environment?

Answer

If session data is stored on one server and the next request reaches a different server, that server may not find the session data, causing authentication issues.

Q9. What are Sticky Sessions?

Answer

Sticky sessions ensure that all requests from a user are routed to the same server instance that stores the user's session data.

Q10. Why is Redis commonly used with Session Authentication?

Answer

Redis is used as a centralized session store so that multiple server instances can access the same session data, improving scalability in distributed systems.

60-Second Interview Summary

Session-based authentication is a stateful authentication mechanism where the server stores user-specific session information and associates it with a unique Session ID. The Session ID is sent to the client through a cookie and included in future requests. The server performs a session lookup using the Session ID to authenticate the user. While session authentication provides easy logout and centralized session control, it introduces scaling challenges in load-balanced environments, which are commonly solved using sticky sessions or shared session stores such as Redis. 🚀
