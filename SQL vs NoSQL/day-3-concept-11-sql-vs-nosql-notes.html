Users

What is SQL?

SQL (Structured Query Language) databases are relational databases that store data in tables consisting of rows and columns.

Examples:

MySQL

PostgreSQL

Oracle Database

SQL databases support relationships between tables using:

  • Foreign Keys
  • Constraints

Company

The database itself understands and enforces these relationships.

Strong Relationships

Supports:

Complex Queries

What is NoSQL?

NoSQL (Not Only SQL) databases are non-relational databases that store data in formats such as documents, key-value pairs, graphs, or wide-column structures.

Examples:

MongoDB

Redis

Apache Cassandra

How NoSQL Stores Data

Example Document:

{
   "name":"Santhosh",
   "department":"CSE",
   "skills":["React","Node.js"]
}

Data is stored as a document rather than rows and columns.

Flexible Schema

Document 1:

{
   "name":"Santhosh"
}

Document 2:

{
   "name":"Rahul",
   "phone":"9999999999"
}

Both are valid.

Top 10 Interview Questions with Answers

Q1. What is the difference between SQL and NoSQL databases?

Answer

SQL databases are relational databases that store data in tables with predefined schemas and support relationships using keys and constraints. NoSQL databases are non-relational databases that store data in formats such as documents and provide flexible schemas designed for scalability.

Q2. Why are SQL databases called relational databases?

Answer

SQL databases are called relational databases because they manage relationships between tables using primary keys, foreign keys, and constraints.

Q3. What is a schema?

Answer

A schema is the blueprint of a database that defines the structure of data, including fields, data types, and constraints.

Q4. Why is MongoDB considered flexible?

Answer

MongoDB allows documents to have different structures and fields without requiring a predefined database schema, making it suitable for evolving data models.

Q5. Does MongoDB support relationships?

Answer

Yes. MongoDB supports relationships using document references and ObjectIds. However, these relationships are managed by the application rather than enforced by the database.

Q6. What is the difference between a Foreign Key and a MongoDB Reference?

Answer

A Foreign Key is enforced by the SQL database and maintains referential integrity. A MongoDB reference is an application-level link between documents and is not automatically enforced by MongoDB.

Q7. What is Referential Integrity?

Answer

Referential integrity ensures that relationships between records remain valid. SQL databases enforce referential integrity using foreign key constraints.

Q8. What is a Dangling Reference?

Answer

A dangling reference occurs when a MongoDB document references another document that has already been deleted, resulting in an invalid relationship.

Q9. Why would you choose SQL for a Placement Management System?

Answer

A Placement Management System contains strongly related entities such as students, companies, applications, and job drives. SQL databases provide data integrity, relationships, transactions, and efficient reporting capabilities.

Q10. Which is better: SQL or NoSQL?

Answer

Neither is universally better. The choice depends on application requirements such as relationships, consistency, scalability, query patterns, and schema flexibility.

60-Second Interview Summary

SQL databases are relational databases that store data in tables and manage relationships through foreign keys, constraints, and referential integrity. NoSQL databases are document-oriented or non-relational databases designed for flexibility and scalability. While MongoDB can model relationships using references, relationship management is handled by the application rather than enforced by the database. SQL is generally preferred for systems requiring strong consistency and complex relationships, while NoSQL is often chosen for flexible and large-scale data workloads. 🚀
